# 值班与故障处置 Runbook

## 事件分级

| 级别 | 定义 | 响应时限 | 示例 |
| :--- | :--- | :--- | :--- |
| S0 | 核心链路不可用/资金数据风险 | 立即 | 网关宕机、支付回调全失败、库存/对账异常 |
| S1 | 主功能不可用但可降级 | 15 分钟 | 下单失败、售后不可用 |
| S2 | 部分功能异常/体验问题 | 4 小时 | 报表延迟、通知失败 |

## 值班矩阵

| 角色 | 职责 |
| :--- | :--- |
| 一线值班（DevOps） | 巡检、告警响应、基础恢复（重启/扩容/回滚） |
| 二线（后端负责人） | 服务与数据问题定位、缺陷修复 |
| 三线（架构/支付专项） | 复杂问题、渠道/合规事项 |
| PM | 对外沟通、升级决策 |

## 标准处置步骤

1. **确认告警**：查看 Prometheus Alertmanager 告警详情与 Grafana 面板。
2. **健康检查**：`kubectl -n oms get pods`；`curl /actuator/health` 各服务。
3. **定位**：
   - 错误率/P99：Grafana HTTP 面板；
   - 日志：`kubectl -n oms logs deploy/<服务> --tail=500`（ELK 就绪后集中检索）；
   - 链路：SkyWalking trace（生产接入后）；
   - 数据库：慢查询日志、`EXPLAIN`、连接池水位。
4. **处置**：
   - 单实例问题：`kubectl -n oms rollout restart deployment/<服务>`；
   - 容量问题：HPA 已自动扩缩，必要时手动 `kubectl -n oms scale deployment/<服务> --replicas=N`；
   - 代码缺陷：`rollout undo` 回滚（见 go-live-playbook §3）；
   - 数据问题：先停止相关写入口（网关限流/Sentinel 熔断），再按数据修复 SOP。
5. **通报**：S0/S1 按模板在值班群通报（影响范围、处理人、ETA、恢复时间）。
6. **复盘**：24 小时内产出事故复盘（根因、改进项、责任人）。

## 常见问题速查

| 现象 | 初步排查 |
| :--- | :--- |
| 网关 5xx | 检查服务注册（Nacos）、下游健康、限流阈值 |
| 支付回调失败 | 检查验签配置、回调地址白名单、重复回调幂等日志 |
| 库存预占失败 | 检查库存流水与事务日志、并发锁等待 |
| 对账差异 | 先看差异单明细（本地/渠道缺失或金额不一致），再决定冲正 |
| 报表无数据 | 检查 Redis 缓存键、归档阈值、数据源连通性 |
