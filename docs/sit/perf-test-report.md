# 性能压测报告

压测环境：本机单实例（Mac，openjdk 21），MySQL/Redis 为 docker-compose 本地实例。
压测工具：ApacheBench（`ab`），参数 `N=5000 C=100`，全部请求无失败。
执行命令：`N=5000 C=100 ./scripts/benchmark.sh`。

## 结果

| 接口 | 吞吐 (req/s) | 平均延迟 (ms) | P99 (ms) | 目标 P99 | 结论 |
| :--- | ---: | ---: | ---: | :--- | :--- |
| 订单分页列表 | 1,319 | 75.8 | 192 | ≤500ms（核心） | ✅ |
| 销售报表汇总 | 4,183 | 23.9 | 55 | ≤1s（查询） | ✅ |
| 销售趋势 | 2,976 | 33.6 | 90 | ≤1s（查询） | ✅ |
| 仓库库存报表 | 2,404 | 41.6 | 113 | ≤1s（查询） | ✅ |

## 已生效的优化

- 报表接口 Redis 缓存（`oms:report:*`，TTL 5 分钟），缓存命中时 P99 显著低于直接查库。
- 报表索引（`paid_at`、`status_paid`、`sku_created`、`channel_created` 等复合索引）随 Flyway 落地。
- 历史订单冷热分离保证热表规模可控。
- 库存扣减流水记录实际出库数量，报表口径准确。

## 规模扩展建议

本地单实例已达标；生产 5,000 QPS 峰值目标需：多实例水平扩展（服务无状态 + Nacos 注册）、报表读写分离或只读副本、Sentinel 限流与 RocketMQ 削峰（均已接入或预留）。
